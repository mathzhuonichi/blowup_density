## 1. Rejected design: a contract that imports the canonical PDE definitions

The first plan was to let `verification/Contracts/V1/Packet.lean` import
`NavierStokes.R3.ProblemStatement` and reuse `VelocityField`,
`navierStokesResidual`, `CompactPositiveTimeSupport`, `l2Sq` and `dissipation`
directly. Those are the pinned upstream statements of the PDE, not our
implementation, so reusing them looked strictly better than copying them.

`experiments/check_contracts.py` forbids it. For any module whose name starts
with `Contracts.` it asserts that every import starts with `Mathlib`, `Lean`,
`Init` or `Contracts.`:

```python
if module.startswith('Contracts.'):
    assert not re.search(r'\b(?:axiom|sorry|admit)\b', code), p
    assert all(x.startswith(('Mathlib', 'Lean', 'Init', 'Contracts.'))
               for x in imports[module]), f'Implementation-dependent specification: {p}'
```

Importing the vendor package would therefore fail `make check`, and relaxing a
trust checker is not something a proof lane should do on its own initiative.

**Decision.** `Contracts/V1/Packet.lean` is self-contained. It writes out the
twenty notions it needs: `Space`, `SpaceTime`, `VelocityField`,
`PressureField`, `coordinateVector`, `preSingularDomain`, `positiveTimeDomain`,
`temporalDerivative`, `spatialDerivative`, `advection`, `spatialDivergence`,
`pressureGradient`, `spatialLaplacian`, `navierStokesResidual`,
`CompactPositiveTimeSupport`, `SquareIntegrableAtTime`, `SpeedUnboundedAtOne`,
`l2Sq`, `dissipation`, `zeroPastField`.

**The risk this creates** is silent drift: an upstream edit could change the
meaning of the canonical definition while the contract keeps the old text, and
nothing would fail. The guard is a block of `rfl` bridge theorems in
`verification/Bindings/Packet.lean`, one per notion, each of which stops
compiling the moment the two sides are no longer definitionally equal. All of
them close by `rfl`; none needed `simp` or a rewrite.

Nineteen of the twenty are also copied character-for-character. The one
exception is `dissipation`: upstream is
`spatialPartial i (fun y => u (t, y)) x`
(`vendor/NavierStokesAndEuler/NavierStokes/R3/CompactEnergy.lean:195`), and the
contract inlines it as
`fderiv ℝ (fun y : Space => u (t, y)) x (coordinateVector i)`, which is exactly
how `NavierStokes.PeriodicIntegration.spatialPartial` unfolds
(`PeriodicIntegration.lean:43-45`). The first version of the module docstring
claimed all twenty were character-for-character; that was false and the
contract reviewer caught it. The docstring now states the defeq claim, names
the `dissipation` exception, and points at the bridges.

## 2. Compile failures

* `import Mathlib.MeasureTheory.Integral.SetIntegral` — **no such module** in
  the pinned Mathlib. `lake build Contracts.V1.Packet` reported
  `bad import 'Mathlib.MeasureTheory.Integral.SetIntegral'`. The set-integral
  notation `∫ x in s, f x` lives in
  `Mathlib.MeasureTheory.Integral.Bochner.Set`, and `IntegrableOn` in
  `Mathlib.MeasureTheory.Integral.IntegrableOn`. Both are imported instead.
* `ContDiffOn ℝ ∞ g preSingularDomain` in
  `formalization/NSFormalization/Section4/I01/Extension.lean` failed with
  `expected token` until `open scoped ContDiff` was added. The `∞` in these
  statements is the `ContDiff`-scoped
  `((⊤ : ℕ∞) : WithTop ℕ∞)` of
  `Mathlib/Analysis/Calculus/ContDiff/FTaylorSeries.lean:120`, i.e. "all finite
  orders". It is not a globally available notation, and in this Mathlib version
  a bare `⊤` would mean the strictly stronger analytic order instead.
* `Real.sqrt` is not in `Mathlib.Analysis.SpecialFunctions.Sqrt` (that file only
  proves smoothness); the definition is in `Mathlib.Analysis.Real.Sqrt:112`.
  Found by grep before writing the import, so this cost no build.

## 3. `obtain` cannot destructure the source existential inside a `def`

`NSFormalization.Source.selected_packet_every_viscosity`
(`Source/ViscosityPacket.lean:131-151`) is an `∃ u p f K, …`. The binding has to
turn that into *named data*, because `PacketAPI` has `velocity`, `pressure`,
`force` and `carrier` as fields. `obtain`/`rcases` cannot do this: `Exists` is a
`Prop` with small elimination only, so destructuring it while the goal is
`Contracts.V1.PacketAPI ν` (a `Type`) is rejected.

The binding uses the `choose` tactic instead, three times — once for the packet
data, once for the quiet time, once for the energy bound. `choose` goes through
`Classical.choose`, so the cost is the `Classical.choice` axiom, which is
already on the allowlist. The resulting transitive axiom set of
`BlowupDensity.Tests.checkedPacket` is exactly
`[propext, Classical.choice, Quot.sound]`, confirmed both by
`TestSupport.checkAxioms` (which reads `Lean.collectAxioms`) and by an
independent `#print axioms`.

`choose` does split the trailing conjunctions of the existential body, so one
invocation handles `∃ u p f K, CandidateProperties ∧ IntegrableOn ∧ early
vanishing` in one go.

## 4. Closed interval `Icc 0 τ` instead of the draft's open germ

`research/I01/REVIEW.md` issue 3 observed that the accepted draft used the open
`Ioo 0 τ` for the three quiet fields, whereas Lemma 2.2
(`paper/sections/02-preliminaries.tex:152`) says `F = 0` on the **closed**
`[0,τ]`. The review suggested keeping `Ioo` and adding a note. The registered
contract instead uses `Icc 0 quietTime` for `force_quiet`, `velocity_quiet` and
`pressure_quiet`, because it turned out to be provable and therefore no
exception was needed:

* the force side comes out closed for free. The new
  `exists_quiet_of_compactPositiveTimeSupport` returns `∀ t ≤ τ, ∀ x, f (t,x) = 0`,
  not a germ, because it picks `τ` strictly below the minimum of the time
  coordinate on the support;
* the velocity and pressure side is `∀ t, |t| ≤ 3/8 → …` from
  `selected_packet_every_viscosity` (`Source/ViscosityPacket.lean:135`), which is
  already a closed condition, and `min σ (3/8) ≤ 3/8`.

The two source lemmas that consume a quiet interval
(`PacketScaling.zeroPastField_smoothOn:373`,
`PacketScaling.zeroPastField_equation:471`) still want the open germ `Ioo 0 ε`,
so `Section4/I01/Extension.lean` weakens `Icc` back to `Ioo` at the point of use
(`fun t ht x => hq t ⟨ht.1.le, ht.2.le⟩ x`). The contract itself is not
weakened anywhere.

A mechanical diff of the registered `PacketAPI` body against the accepted draft
`research/I01/Spec.lean`, doc comments stripped, gives 45 field lines on each
side with exactly three differing — those three `Ioo` → `Icc` changes.

## 5. Fields that needed a lemma not present in the sources

Four groups. Everything else in `PacketAPI` is a projection of
`NavierStokesR3.ProblemStatement.CandidateProperties` as produced by
`selected_packet_every_viscosity`.

**`quiet_pos`, `quiet_lt_one`, `force_quiet`** — new:
`Section4.I01.exists_quiet_of_compactPositiveTimeSupport` and
`Section4.I01.exists_packet_quiet` (`Section4/I01/Quiet.lean`).
No source lemma derives a quiet interval from `CompactPositiveTimeSupport`.
`SelectedPacketEnergy.selected_early_energy_packet` does have a force germ at
`τ = 3/8`, but `selected_packet_every_viscosity` does not re-export it, and
`3/8` is an artifact of the OpenAI time switch rather than of the manuscript's
argument. The new lemma is the manuscript's own reasoning: `Prod.fst` is
continuous and `tsupport F` is compact and contained in `Ioi 0 ×ˢ univ`, so
`IsCompact.exists_isMinOn` gives a point of the support with minimal time
coordinate, which is strictly positive; any `τ` below it works. The empty
support case is handled separately with `τ = 1/2`.

**`energy_isLUB`** — new: `Section4.I01.exists_l2_isLUB`
(`Section4/I01/Energy.lean`). The sources give only *an* upper bound, and for
kinetic energy `½∫‖u‖²` (`UniformFiniteEnergy`,
`vendor/.../R3/ProblemStatement.lean:81-83`), not for `‖U(t)‖₂`. The least
upper bound is built with `Real.exists_isLUB`: nonemptiness from `0 ∈ [0,1)`,
boundedness by `√(2E)` since `½·l2Sq u t ≤ E`. A plain upper bound would not
be enough, because `eq:packetEscale` (`paper/sections/03-torus.tex:125-126`)
asserts the *equality* `‖U_ε‖_{L^∞(0,T;L²)} = ε^{1/2}M`.

**`extension_divergence_free`** — new:
`Section4.I01.extension_divergence_free` (`Section4/I01/Extension.lean`). The
argument existed only inlined inside
`PacketScaling.delayed_parabolic_divergence` (`Source/PacketScaling.lean:506-523`)
and only for the already-rescaled field. The un-rescaled statement
`∀ t < 1, ∀ x, spatialDivergence (zeroPastField U) t x = 0` had no name. The
proof is the same case split: at positive times the spatial slice is unchanged,
at nonpositive times it is constantly zero so its `fderiv` vanishes.

**`velocity_extension_smooth`, `pressure_extension_smooth`,
`extension_navier_stokes`** — new wrappers
`Section4.I01.extension_smoothOn` and `Section4.I01.extension_navierStokes`,
but no new mathematics. `PacketScaling.zeroPastField_smoothOn` and
`zeroPastField_equation` already prove exactly these. The wrappers convert the
closed quiet interval to the open germ and restate the equation with
`NavierStokesR3.ProblemStatement.navierStokesResidual ν` in place of
`NSFormalization.Source.residual ν`. Those two are definitionally equal
(`Source/Insertion.lean:21-24` versus
`vendor/.../R3/ProblemStatement.lean:57-62`), so the restatement closes with no
rewrite at all.

## 6. Split units from `COMPARISON.md` that turned out unnecessary

* **Unit 3, `packet_dissipation_norm`.** The contract only asserts
  `D = √(∫_{Ioo 0 1} dissipation U)`, so the binding defines `dissipationBound`
  to be literally that expression and `dissipation_eq` is `rfl`. No `0 ≤ D` and
  no `D² = ∫ …` lemma is consumed by any field, so neither was written. Add
  them when I03 actually needs them.
* **Unit 7, `packet_force_zero_nonpos`.** One application of the existing
  `CompactPositiveTimeSupport.eq_zero_of_nonpos`
  (`vendor/.../R3/ProblemStatement.lean:173-178`). Kept inline in the binding
  rather than given its own module.
* **The "faithful" route to velocity and pressure vanishing** —
  `PacketEnergy.vanishes_before_forcing` (`PacketEnergy.lean:197-229`) and
  `PacketPressure.pressure_vanishes_on_quiet_interval`
  (`PacketPressure.lean:55-69`) — was **not** used.
  `selected_packet_every_viscosity` already re-exports the closed `|t| ≤ 3/8`
  vanishing, which is what split unit 8 prescribed, and using it keeps the
  binding a pure assembly with no PDE reasoning of its own. The faithful route
  stays available and is the one to switch to if the `3/8` ever has to go,
  since it derives the vanishing from the energy estimate rather than from the
  OpenAI time switch.

## 7. The lost Attempts section, and why this file exists

The first pass appended this record to the end of
`collaboration/tasks/I01.md`, following `CLAUDE.md` rule 4. It did not survive
the commit. `experiments/tasks.py:41` renders each card with

```python
(ROOT / f'collaboration/tasks/{node["id"]}.md').write_text('\n'.join(lines) + '\n')
```

so the `tasks.py render` run that flipped the card's line to
`Registered component contracts: I01.packet.` rewrote the whole file and
discarded everything appended below it. The contract reviewer independently
confirmed this by re-running `render` in a throwaway copy and finding all
thirty cards byte-identical to the committed ones.

Consequence, and the coordinator's decision: attempts records never go into
`collaboration/tasks/*.md`. They go into `research/<ID>/ATTEMPTS.md`, which is
not generated.

## 8. Contract review round (`research/I01/REVIEW_CONTRACT.md`)

ACCEPT-WITH-NOTES. Three notes were applied in a second pass; no Lean term
changed, only bridges, prose and one registry string.

* **Drift-guard gap.** Eight notions had no direct bridge. Five one-line `rfl`
  theorems were added to the binding — `temporalDerivative_eq`,
  `spatialDerivative_eq`, `advection_eq`, `pressureGradient_eq`,
  `spatialLaplacian_eq` — so the four operators are no longer guarded only
  through the composite `navierStokesResidual_eq` (which would survive two
  compensating upstream edits), and `spatialDerivative` no longer only through
  `spatialDivergence_eq`. The binding now carries 19 bridge theorems covering
  17 of the 20 notions. The three still without one are the reducible type
  abbreviations `SpaceTime`, `VelocityField` and `PressureField`, whose defeq
  is already forced by every other bridge that mentions them; the docstring
  says so explicitly rather than overclaiming.
* **False docstring claim.** "character-for-character" replaced as described in
  section 1 above.
* **Scope wording.** The registry said "the Theorem 1.1 properties" while the
  contract deliberately omits Theorem 1.1's nonexistence corollary
  (`paper/sections/01-introduction.tex:30-33`, Lean
  `¬ Nonempty GlobalFiniteEnergySolution`, which belongs to node `U01` and which
  Section 4 never invokes). The scope now reads "the Theorem 1.1 construction
  properties (not its nonexistence corollary) plus Lemma 2.2 and the zero
  extensions, for every ν>0; not the local insertion theorem and not any
  density statement."
* **Cosmetic, applied.** The `preSingularDomain` and `positiveTimeDomain` doc
  comments wrote `R^3 x [0,1)` and `R^3 x (0,∞)` while the Lean terms are
  time-first (`Ico 0 1 ×ˢ univ`, `Ioi 0 ×ˢ univ`). Both now read time-first.
  The two extension fields were already time-first (`(-∞,1) × R³`) and were
  left alone.
* **Left open, out of contract scope.** `REVIEW.md` notes 1, 2, 7 and 8 concern
  `COMPARISON.md` only (the `energy_isLUB` and `pressure_support` rows, two
  off-by-one line ranges, and follow-up A). `COMPARISON.md` was not edited by
  this lane. None of them affects `Packet.lean`, the binding or the registry.
