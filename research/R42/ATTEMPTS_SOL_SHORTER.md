## Traps / adjusted approaches (load-bearing for the binding lane)

1. **`continuous_slice_of_velocity_smooth` (lane 080) is `Ioo`-only; reuse
   `D01.contDiff_slice` for the `Ico` form.**  Lane 080's lemma concludes
   `∀ t ∈ Ioo 0 T, Continuous …`, but `sobolev_add_of_localized`'s `hvc`/`hdc` are
   on `Ico 0 S` and are *used at `t = 0`* (the `sobolev` field of
   `ClassicalSolutionR` runs over `Ico 0 S`).  The `Ico`-including-`t = 0` vector
   slice smoothness is exactly `D01.contDiff_slice` (`D01/DatumToJets.lean:366`);
   `(D01.contDiff_slice hv ht).continuous` gives both hypotheses.  *(Corrected per
   lane-087 review finding 2.)*  The first draft inlined a byte copy
   `contDiff_slice_velocity` under the belief that importing `D01.DatumToJets`
   would drag a ≈550-module closure into the file — **that measurement was for
   `R42.PressureGradient` (whose only import is `A02.SolutionClass`), not for this
   module.**  This module already imports `D01.ForceClass` transitively through
   `R42.CorrectionPath`, so `D01.DatumToJets` adds only **two** modules
   (`A05.SmoothJets`, `DatumToJets`), both already built (+0.37 s, ≈9 %); REVIEW_PRESSURE
   finding 4's own "For completeness" paragraph anticipates exactly this case.  So
   the copy was deleted and `D01.contDiff_slice` is used directly.

2. **`navierStokesResidual` namespace.**  `ClassicalSolutionR.momentum`
   (`A02/SolutionClass.lean:130`) uses **`NavierStokesR3.ProblemStatement.navierStokesResidual ν …`**
   (takes the viscosity `ν`).  The identifier `navierStokesResidual` brought in by
   `open NavierStokes.ProblemStatement` is the **base** one
   (`vendor/…/NavierStokes/ProblemStatement.lean:82`, **no** `ν`, viscosity 1).
   Writing `navierStokesResidual ν u p t x` under only that open is an arity
   error.  `hmom` is therefore stated with the fully-qualified R³ name so it
   matches the field by `exact` after `Ioo 0 S ⊆ Ioo 0 T`.

3. ~~**`Set.Ico_subset_Ico_right` / `Set.Ioo_subset_Ioo_right` do not exist** in
   the `Set` namespace…~~ **FALSE — struck (lane-087 review finding 1).** Both
   `Set.Ico_subset_Ico_right` and `Set.Ioo_subset_Ioo_right` **do** exist and work
   as drop-ins (`Set.Ico_subset_Ico_right hST.le : Ico 0 S ⊆ Ico 0 T`).  They are
   generated by `@[to_dual]` from the `_left` versions
   (`Mathlib/Order/Interval/Set/Basic.lean:281-290`), so a source `grep` for
   `theorem Ico_subset_Ico_right` finds only the `Finset` copy and wrongly concludes
   the `Set` one is absent.  **Real lesson: `to_dual`-generated names are invisible
   to source grep — existence must be tested with `#check`, never grep.**  The
   committed code uses the two-sided `Set.Ico_subset_Ico le_rfl hST.le` /
   `Set.Ioo_subset_Ioo le_rfl hST.le` (`…/Set/Basic.lean:271,281`), which is
   correct and idiomatic; the `_right` forms would have been equally fine.

4. **`simp only [hd_def]`, not `dsimp only`.**  `d` is a `set` binding; `dsimp only
   [hd_def]` makes no progress on it (CorrectionPath lane-075 friction 1).
   `simp only [hd_def]` unfolds and beta-reduces `d (t,x)` to
   `u (t,x) - ref.velocity (t,x)`, after which `hvsupp`/`sub_eq_zero_of_eq`/`abel`
   apply.
