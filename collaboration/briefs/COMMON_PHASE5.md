# Phase 5 common rules for closing a Partial entry (read with your lane brief)

**Context.** The owner's `main` (2026-09-21, commit `1a1b53b6`) merged Sections 3–4 (55 lanes) and then streamlined the repository: 29 registered contracts (`verification/contracts.json`), an article-level proof graph (`formalization/blueprint/proof_graph.json` → generated `DEPENDENCY_GRAPH.md`), `RESULT_MAP.md`, `CLOSURE_AUDIT.md`, `AXIOM_AUDIT.json`, `entrypoints.json`, and a guide `paper/formalization_guide.tex` (PDF `output/pdf/formalization_guide.pdf`). Six article entries are **Partial**; our branch `erenup/core` = `main` + the lead's process layer (`research/`, `logs/`, `collaboration/briefs/`, `scripts/`, `PLAN.md`). Read `README.md`, `experiments/README.md`, `verification/README.md`, `formalization/blueprint/README.md`, `logs/LESSONS.md` (top 40 lines — in particular the 2026-09-20 entry: an elementary identity is never left as a residual before trying the zero-extension / compact-support route).

**Ground rules (non-negotiable).**
- Work ONLY inside your worktree; never `git push`, merge or rebase; commit on your branch **after each closed step** (skeleton within 15 minutes). `. scripts/lean-env.sh`; `lake` only from `verification/` with `LEAN_NUM_THREADS=6`. Build the closure you need first.
- No `sorry`/`admit`/`axiom`/`native_decide`; `set_option maxHeartbeats N in` only per declaration, `N ≤ 400000`, commented. New files by default; edit an existing module only when the brief authorises it (record every such edit in your ATTEMPTS file). Never re-import removed modules (`Paper1/BoundaryCorollary.lean` etc. are gone).
- **No named inputs, no placeholders, no goal repackaging.** An honest partial with the exact residual statement and error text beats a stub. A "not in Mathlib" claim needs a second, elementary attempt before it becomes a residual.
- Every declaration prints exactly `[propext, Classical.choice, Quot.sound]`. `grep -rn` before claiming "not in the tree"; `sed -n` before citing a line.
- Statement fidelity: the target is the **article's** statement (`paper/revised/sections/*.tex`, revised numbering) — quote the exact lines you formalise in the module docstring; keep the reconciled records of `research/T*/Spec.lean` as the vocabulary.

**Closing procedure (do in this order, committing after each).**
1. Lean: the canonical theorem(s) in `formalization/NSFormalization/…`, a probe under `research/<node>/probes/`, an axioms file `research/<node>/axioms_<lane>.lean`, `ATTEMPTS_<lane>.md`.
2. Contract: V2 (or new) statement token-for-token in `verification/Contracts/V2/<Name>.lean` (import the V1 module; pattern: `Contracts/V2/BoundaryInsertion.lean`), binding `verification/Bindings/<Name>V2.lean`, test `verification/Tests/<Name>V2.lean` (pattern: `Tests/BoundaryInsertionV2.lean`: `checked…` theorem + `run_cmd TestSupport.checkAxioms`), registry entry in `verification/contracts.json` (shape of `T23.boundary_insertion_v2`: `id`, `parent_task`, `version`, `specification`, `binding_module`, `test_module`, `declaration`, `scope`, `enabled`; keep the V1 entry).
3. Blueprint: in `formalization/blueprint/proof_graph.json` set the node's `status` to `Closed`, rewrite its `scope` to the exact clause now proved, point `evidence` at the new modules, and replace `completion_from` by `depends_on` (the checker requires `completion_from` only on Partial nodes and forbids Closed→Partial dependencies); add the new proof modules to `entrypoints.json`; update the `RESULT_MAP.md` row (Coverage + locations with `#L<line>` anchors); update the `\coverage{Partial}` row of `paper/formalization_guide.tex` to `\coverage{Closed}` with the new `\source{…}` entries and a one-line scope; update the "21 Closed and 6 Partial" counts in `README.md`, `DEPENDENCY_GRAPH.md` (regenerated) and `CLOSURE_AUDIT.md`. Then `python3 experiments/check_formalization_plan.py` (regenerates `DEPENDENCY_GRAPH.md`), `python3 experiments/audit_article_axioms.py --build --output-dir tmp/article-audit --workers 2` (and update `AXIOM_AUDIT.json` the way the script/README prescribes — read the script header first), `make check`, `make test`, `make test-mutations`, `make paper` (LaTeX is installed).
4. Report `research/<node>/REPORT_<lane>.md`: four parts (statements / files / gaps with error text / commands and results), and a status line in the relevant `research/<node>/*_SPLIT.md` or `SPEC_ISSUES.md`.
